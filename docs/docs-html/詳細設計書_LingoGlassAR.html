■ §1　本書の位置づけ・前提
本書の対象LingoGlass AR MVP の 内部実装方法（HOW）を確定する。クラス構造・関数シグネチャ・エラーコード・環境変数・ディレクトリ配置までを定義し、開発者が手戻りなしに実装に入れる状態にする。
対象読者Firmware / Mobile / Backend Engineer、QA、AI agents（コード生成補助）
記述レベル関数シグネチャ・クラス図・状態遷移までを記述。実コード（メソッド本体）は対象外。
技術スタック（lock-in） ・Firmware: ESP-IDF 5.x (C/C++17) on ESP32-S3
・Mobile: Flutter 3.22 / Dart 3.4（iOS 16+ / Android 11+）
・Backend: Node.js 20 LTS + Express 4 + ws 8 + TypeScript 5.4
・DB: PostgreSQL 16（Drizzle ORM）／ Redis 7（任意）
・Infra: Fly.io（東京リージョン nrt）／ S3 互換ストレージ（Backblaze B2）
採用パターン ・レイヤード：Handler → Service → Repository
・依存性注入：コンストラクタ DI（DI コンテナ未使用 — `index.ts` でワイヤー）
・エラーは AppError(code, message, status) 統一型でレスポンスへ変換
・Flutter は features/ 単位の Riverpod ベース状態管理

4.1　主要 UC 仕様書（UC-02 会話字幕）
UC-IDUC-02 名前会話の字幕を表示する
主アクターエンドユーザー 2 次アクターCloud AI（STT/翻訳）、LingoGlass
事前条件グラスとペアリング済み（devices.is_active = true）、ネットワーク到達可能、マイク権限付与済み。
基本フロー ① ユーザー SCR-03 を開く ② アプリが WSS /api/v1/session を確立し、sessions レコードを active で作成 ③ マイク収音 + VAD で発話区間を切出し、Opus エンコードで chunk を送信 ④ サーバーが STT → Translate を逐次実行 ⑤ 翻訳テキストをアプリへ返却 ⑥ アプリが PacketBuilder で BLE フラグメントに分割 → グラスへ送信 ⑦ グラスが字幕レンダリング、ACK を返す ⑧ 各ステップの timestamp を session_events へ記録
例外フロー E1 WSS 切断 → 5 秒以内に再接続。失敗時 SCR-03 にエラーバナー。
E2 STT/翻訳タイムアウト（5s） → エラー結果を BLE で「— 翻訳できませんでした —」として表示。
E3 BLE 切断 → 自動再接続（最大 30s）。再接続中は字幕送信を抑止。
事後条件sessions.status='ended'、ended_at 設定。SCR-06 で p50/p90/p95 が確認できる。

6.1　状態遷移（PowerManager / 字幕表示）
[OFF] --power on--> [BOOT] --ble_init ok--> [ADVERTISING]
    [ADVERTISING] --connect--> [READY]
    [READY]       --subtitle pkt--> [DISPLAYING] (字幕表示)
    [DISPLAYING]  --subtitle clear / 30s--> [READY]
    [READY]       --60s 無活動--> [SLEEP] (display off, BLE notify keep)

6.2　IPO 図 — 字幕パケット受信処理（main loop）
InputProcessOutput
BLE write characteristic からのバイナリバッファ（最大 MTU - 3 bytes） ① CRC8 検証（失敗 → NAK 0x31 返信）
② version, type, seq, frag_index, frag_count, payload_len を解釈
③ PacketAssembler.feed(pkt)
④ 新 sequence_id → 旧進行中破棄（discard_old）
⑤ 全 fragment 揃ったら DisplayRenderer.render(text)
⑥ ACK 0x30 を返信		 ① 字幕がディスプレイへ描画される
② ACK / NAK を BLE notify で送信
③ 5 秒タイムアウト：sequence 破棄ログ（任意）
5 秒経過した PacketAssembler のタイマー tick ① is_complete() false かつ deadline 超過 → assembler reset
② Optionally Send STATUS_REPORT (timeout) to App		 ① 壊れた fragment セットが破棄される
② アプリ側は再送せず、新しい字幕の到着を待つ

FROM node:20-alpine AS builder
WORKDIR /app
COPY pnpm-lock.yaml package.json ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY . .
RUN pnpm build

FROM node:20-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY package.json ./
ENV NODE_ENV=production
EXPOSE 8080
USER node
HEALTHCHECK --interval=30s --timeout=5s \
  CMD wget -qO- http://localhost:8080/api/v1/healthz || exit 1
