■ §1　本書の位置づけ・命名規則
本書の対象 LingoGlass AR MVP プロトタイプにおける「ユーザーから見える部分」の外部設計を確定する。詳細実装（クラス・関数シグネチャ）は次工程の詳細設計書 DD-LGA-001 で扱う。
読者 Product Lead、Firmware / Mobile / Backend Engineer、パイロットレビュー担当、AI agents
対象範囲 モバイルアプリ（6 画面）／ バックエンド API（WebSocket + REST 3 本）／ BLE プロトコル ／ データ設計 ／ クラウド AI 連携。グラス側ファームウェアの詳細実装は対象外（詳細設計書で扱う）。
命名規則 ・テーブル：snake_case、複数形（例: sessions）
・主キー：id（UUID v4）
・外部キー：[参照先単数形]_id（例: session_id）
・タイムスタンプ：created_at / updated_at（TIMESTAMPTZ）必須
・フラグ：is_ prefix／ステータス：VARCHAR + CHECK 制約（enum はコード一覧と一致）
・画面 ID：SCR-NN ／ 機能 ID：FR-{HW|APP|BE|OPS}-NN ／ API：/api/v1/...

■ §10　BLE 字幕プロトコル仕様（カスタム GATT）
10.1　パケット構造
┌─────────────────────────────────────────────┐
│ 0  version          (1 byte)  — 0x01        │
│ 1  message_type     (1 byte)  — see 10.2    │
│ 2  sequence_id      (2 bytes) — uint16 LE   │
│ 4  fragment_index   (1 byte)  — 0-based     │
│ 5  fragment_count   (1 byte)  — total       │
│ 6  payload_length   (1 byte)  — N (0-236)   │
│ 7  payload          (N bytes) — UTF-8       │
│ 7+N crc8            (1 byte)  — CCITT       │
└─────────────────────────────────────────────┘
1 packet 全体 = 8 + payload_length bytes
ATT MTU から payload_length 最大値を求める式：
  max_payload = mtu - 3 (ATT) - 8 (本プロトコルヘッダ＋CRC)
最大ペイロード 1 パケット：236 bytes (@ MTU 247)
                          174 bytes (@ MTU 185)
                           12 bytes (@ MTU 23 ＝ BLE 最小)
10.2　メッセージタイプ
値名前方向
0x01SUBTITLEApp → Glass
0x02STATUS（バッテリー、温度など、Phase F+）Glass → App
0x03ACK（status code 付き、§10.4）Glass → App
0x04ERROR（予約、現状未使用）Both

SUBTITLE_CLEAR / OTA_UPDATE / 専用 NAK type は MVP に含めない。失敗は ACK の status code で表現する（§10.4）。

10.3　レンダリングルール
  • 全 fragment が揃った時点で初めて描画する
  • 新 sequence_id 受信時、進行中の旧 sequence は破棄（partial render しない）
  • CRC8 不一致は ACK status=0x03 で返信、再送はアプリ側判断
  • fragment タイムアウトはアプリ側 300ms × 最大 2 retry でハンドリング
  • MVP 字幕上限 100 文字（UTF-8 で約 300 bytes）= 最大 2 fragment（MTU 247 時）
10.4　実装固定値（S0/S1）
Service UUID7c3d8b00-9e8a-4f15-b6c3-1d2e3f4a5b6c
Subtitle Write Char7c3d8b01-9e8a-4f15-b6c3-1d2e3f4a5b6c
