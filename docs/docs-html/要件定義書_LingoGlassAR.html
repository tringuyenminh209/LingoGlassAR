■ §1　システム概要
システム名 LingoGlass AR（リンゴグラス AR）
目的・背景 海外旅行・多言語コミュニケーション場面において、スマートフォンを手に持たずに翻訳字幕を視界内に表示することで、会話の自然さと利便性を向上させる。現行の翻訳アプリは「取り出す→画面を見る→ボタンを押す」という動作が会話を中断させる課題がある。LingoGlass AR はこの摩擦をゼロに近づけることを目指す。
MVP アーキテクチャ グラス：字幕表示（Micro-OLED / Waveguide）+ BLE/Wi-Fi コントローラー（ESP32-S3）
スマートフォン：ゲートウェイ（音声収音・OCR 撮影・クラウド中継）
Cloud AI：STT・翻訳・OCR 処理・診断ログ収集
対象ユーザー ① 海外旅行者（日本・韓国・台湾等）：看板・メニュー・案内を読めない
② 留学生・外国人労働者：日常会話の継続的なサポートが必要
③ 観光・小売・ホテル接客スタッフ：外国人客への即時対応
④ 出張ビジネスパーソン：多言語会議・商談の字幕サポート
開発体制 Solo founder 1 名 + AI agents（設計・コーディング・テスト補助）
前提・制約 ・量産・販売は本フェーズの対象外。プロトタイプ × 1〜2 台で KPI を検証する。
・グラス本体にマイク／カメラは搭載せず、スマートフォン側のセンサーを使用する。
・BLE を主接続、Wi-Fi はデバッグ用フォールバックとする。
■ §2　現状と課題
2.1　現状の問題（As-Is）
No 問題（What's wrong） 原因 ユーザーへの影響
1 翻訳のたびにスマートフォンを取り出す必要がある 現行の翻訳アプリはすべてスマートフォン画面を媒体とする 会話が中断し、相手に失礼・コミュニケーション品質が低下する
2 翻訳結果が視界外にある（画面を低く見る必要） スマートフォンは手元・胸ポケット等に保持するため視線が外れる 会話相手と目が合わない・自然な対話が困難
3 看板・メニュー等のテキスト翻訳に手間がかかる アプリを開く→カメラ起動→撮影→OCR 待機という複数手順が必要 観光・食事・移動時の判断が遅れる
4 既存 AR グラス（Xreal 等）は重く、翻訳専用ではない エンターテイメント・業務向けの汎用設計。翻訳 UX は後付け 長時間装着の不快感・翻訳精度・遅延への不満
5 Ray-Ban Meta 等は字幕表示ディスプレイを持たない カメラ・マイク搭載だが光学表示系なし（スピーカーのみ） 翻訳結果を"見る"ことができず、騒音環境では使えない
2.2　ヒアリング結果サマリー（n = 12 / 想定ユーザー）
セグメント人数期待すること・目標主な発言・観察
海外旅行者4スマートフォンを取り出さずに看板・メニューを読みたい「両手に荷物を持っているとアプリを起動するのが面倒」「飲食店で店員と目を合わせて注文したい」
留学生／外国人労働者3日常会話の聞き取り補助。長時間装着の快適性を重視「授業の専門用語が分からない時だけサポートが欲しい」「重い・熱いと授業中つけられない」
接客スタッフ（飲食・小売）3レジ・案内中にハンズフリーで翻訳を確認したい「タブレット翻訳機は手が塞がる」「両手で商品を持ちながら話す場面が多い」
出張ビジネス2会議・商談での字幕サポート。記録・要約も欲しい「会議中にスマートフォンを見ると失礼」「録音は法務的に NG なケースも多い → 字幕のみ表示で十分」
共通要望： ① 取り出し動作ゼロ　② 字幕は短く・読みやすく（1〜2行）　③ プライバシーが明示的に守られていること（録音中の表示）　④ バッテリーは半日もてば許容

■ §3　ゴール（到達目標）
3.1　定量 KPI（MVP プロトタイプ検証基準）
NoKPI目標値備考
K-01会話字幕 End-to-End 遅延（p50）≤ 2.0 秒VAD → STT → 翻訳 → BLE → 表示 合計
K-02会話字幕 End-to-End 遅延（p95）≤ 3.5 秒3.5 秒超が常態化 → No-Go 判断
K-03OCR 翻訳表示時間≤ 3.0 秒撮影 → OCR → 翻訳 → 表示
K-04アクティブ使用時間（連続）≥ 2 時間プロトタイプ許容値。量産目標 8 時間
K-05混合使用時間（standby 込み）≥ 6 時間日常観光シナリオ
K-06屋外視認性（明るい屋外）≥ 80%テスター ≥ 10 名中 80% 以上が「読める」と評価
K-07BLE 接続エラー（30 分テスト中）≤ 2 回BLE 再接続含む
K-08継続使用意向（パイロット）≥ 40%「また使いたい」と回答したテスター割合
K-09クラウドコスト（パイロット 50 名）≤ $550 USD / 月STT + 翻訳 + OCR + infra 合算
3.2　定性ゴール（プロトタイプ完了時の状態）
  • 外国語の会話を聞いた直後に、グラスの字幕で翻訳が読める体験を実証できる
  • スマートフォンを持ち続けなくても翻訳が受けられる "hands-free" 体験が実現できる
  • カメラで看板・メニューを撮影するだけで翻訳が字幕として表示される
  • 30〜60 分連続装着しても熱・重量が不快でないことが確認できる
  • 収音中・撮影中であることが周囲の人にも視認できる（プライバシー確保）

4.2　OUT スコープ（MVP には含めない）
No対象外機能理由
O-01AI エージェント（自動予約・経路案内）字幕表示の実証が優先。AI エージェントはフェーズ 3 以降
O-02グラス上のマイク・カメラMVP はスマートフォンのマイク・カメラを使用しリスク低減
O-03完全オフライン翻訳（グラス単体）クラウド利用が前提のため MVP 外
O-04話者識別（Speaker ID）複数人環境での識別は精度・遅延双方のリスクが高い
O-05Kubernetes / マイクロサービス基盤プロトタイプに不要。シンプルな WebSocket サーバーで十分
O-06量産・クラウドファンディングプロトタイプが KPI を達成した後に検討
O-07処方箋レンズ対応視力矯正レンズとの併用は量産フェーズで対応

■ §5　基本要件と優先順位（MoSCoW）
優先度分類内容
Must（必須）ハードウェア基盤BLE → ESP32-S3 → ディスプレイへの字幕送信・表示が安定動作すること（Spike Pass）
Must（必須）会話字幕スマートフォンマイク収音 → STT → 翻訳 → 字幕表示の End-to-End 遅延 p50 ≤ 2.0s
Must（必須）OCR 翻訳スマートフォンカメラ撮影 → OCR → 翻訳 → 字幕表示 ≤ 3s
Must（必須）プライバシー収音中・撮影中を物理 LED で通知（デフォルトは音声・映像の生データを保存しない）
Must（必須）診断ログ遅延・バッテリー・接続エラーを計測・記録し、Go/No-Go 判断に使用できること
Should（重要）言語設定ソース言語・ターゲット言語をアプリから再起動なしに変更できる
Should（重要）接続状態表示アプリに接続・バッテリー・エラー状態をリアルタイム表示
Should（重要）再接続回復BLE 切断時の自動再接続。30 秒以内に字幕が再開すること
Could（あれば）翻訳履歴デフォルト OFF。ユーザーがオプトインで有効化できる翻訳履歴
Could（あれば）Push-to-Talk常時収音ではなくボタン押下中のみ収音するモード
Could（あれば）セッション要約会話終了後の要約レポート（オフラインバッチ処理）

FR-APP-03 会話字幕モード 音声収音・VAD マイク収音・音声区間検出（VAD）・無音カット 高 短文（5〜10 語）を適切に 1 発話として切り出せる

FR-APP-05 字幕グラス送信 翻訳テキストを BLE でグラスに送信・表示確認 高 グラス上で字幕が視認できる
