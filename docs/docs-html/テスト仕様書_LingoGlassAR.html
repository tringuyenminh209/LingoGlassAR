■ §1　テスト方針・進入/退出基準
テスト目的LingoGlass AR MVP が REQ-LGA-001 の要件（特に KPI K-01〜K-09）を満たすことを段階的に検証し、Go/No-Go 判断に必要な客観的データを生成する。
テストレベル① 単体（UT）→ ② 結合（IT）→ ③ 総合（ST）→ ④ 受入（UAT）の 4 段階。各段階で 退出基準 を満たさない場合は前段階へ戻す。
テスト戦略 ・自動化：UT は vitest（Backend）/flutter test（Mobile）/unity（Firmware）
・契約：BLE プロトコルは TS 実装 / Dart 実装の fixtures 共有テスト で互換性検証
・正常系 + 異常系を必ず両方記述（境界値分析・マトリクス手法）
・パフォーマンス：診断ログ（FR-APP-10）の p50/p90/p95 を機械的に集計
進入基準UT 開始：当該モジュールのコードが master へマージ済み。IT 開始：UT 通過率 100%（既知 NG は障害登録）。ST 開始：IT 主要シナリオ全て pass。UAT 開始：ST の Critical 障害ゼロ。
退出基準 ・UT：カバレッジ ≥ 70%（コア層 Service/Provider ≥ 85%）、全 pass
・IT：プロトコル契約テスト 100%、主要 5 シナリオ pass、リグレッション NG ゼロ
・ST：KPI K-01〜K-07 を 1 回以上達成、Critical/重大 障害ゼロ
・UAT：パイロット n ≥ 5、K-08（継続意向 ≥ 40%）達成

5.2　境界値マトリクス — BLE パケットペイロード長
条件 最小未満 最小 正常範囲 最大 最大超
payload_length（@ MTU 247、上限 238） -1（不正）→ NG 0 bytes → OK 1〜237 → OK 238 → OK 239 → NG（BAD_LENGTH）
字幕文字数（UTF-8） — → — 0 文字 → OK 1〜100 → OK 100 → OK 101 → NG（truncated + warn）
fragment_count 0 → NG 1 → OK 1〜4 → OK 4 → OK 5 → NG（超過、disc）
MTU 19 → NG（contract violation） 20 → OK 185 → OK 247 → OK 248 → NG（仕様外）
5.3　境界値マトリクス — Quota / セッション
条件 最小未満 最小 正常範囲 最大 最大超
device_id 日次リクエスト数 — 1 → OK 2〜999 → OK 1000 → OK 1001 → 429 QUOTA_EXCEEDED
OCR 画像サイズ 0 byte → 400 1 byte → OK 1KB〜4MB → OK 4 MB → OK 4 MB + 1 → 413
セッション同時数（1 device） — 1 → OK 1 のみ → OK 1 → OK 2 → 既存切断 + 新規受付
BLE 再接続待機時間 — 0s（即時）→ OK 1〜29s → OK 30s → OK 31s 以上 → UC-02 中止、ユーザー通知
境界値テストは「ちょうど境界」での挙動を必ず確認。最小未満／最大超は 異常系として扱い、適切なエラーレスポンス が返ることを検証する。
