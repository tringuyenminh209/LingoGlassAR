# 日報 2026-05-29（S3 Day 5）

## 本日の作業

S3 Day 5 — 実機 OCR スモーク（Galaxy S10）。recognise -> translate -> OLED 描画を端から端まで実機で初通し。三件の不具合を切り分けて修正、最終 **PASS**。

### 不具合 1: 撮影一発目でアプリがクラッシュ

- `ClassNotFoundException: com.google.mlkit.vision.text.japanese.JapaneseTextRecognizerOptions$Builder`。
- 原因: `google_mlkit_text_recognition` プラグインは Latin モデルのみ同梱し、JP/CN/KR/Devanagari は `compileOnly`（app size 削減のため）。Latin は動くのでアプリ起動は通るが、`TextRecognitionScript.japanese` を呼んだ瞬間にクラスが無く落ちる。
- 修正: `mobile/android/app/build.gradle.kts` に `implementation("com.google.mlkit:text-recognition-japanese:16.0.1")` を追加（プラグイン同梱の text-recognition:16.0.1 にバージョンを合わせる）。**bundled モデル**なので Day 1 で懸念した初回モデルダウンロードのリスクも同時に解消、認識は完全オンデバイスのまま。

### 不具合 2: 「Translation failed」

- `/healthz` は 200 なのに `POST /v1/translate` が 404。
- 切り分け: エンドポイントは `main` に存在（`main.py` が `translate_router` を mount、`7ad32f0`/`731d425`）。つまり EC2 が Day 2 以前のビルドで稼働していた = **デプロイずれ**。コード修正は不要。
- オペレーターが再デプロイ（`git pull` + `docker compose up -d --build`）。`curl POST /v1/translate` で 200 + translatedText を確認、ライブ化。

### 不具合 3: 小さい文字に対して撮影が甘い

- カメラが `ResolutionPreset.high`（~720p）かつ能動的なフォーカス無しで、メニュー/看板の小さな字が滲む。
- 修正（`ocr_screen.dart`）: `veryHigh`（~1080p）へ引き上げ、init 後に `setFocusMode(auto)` + `setExposureMode(auto)`、プレビューにタップフォーカス（`setFocusPoint`+`setExposurePoint`）を追加。max は撮影が遅く OCR 時間を膨らませるだけなので不採用。
- オペレーターが再撮影し、より鮮明になったことを確認。

### スモーク結果

- **PASS**: 実機で recognise -> translate -> OLED 描画が端から端まで成立。
- プライバシー境界は維持: 画像はオンデバイス OCR で即削除、認識/翻訳テキストは画面表示のみでログ/保存なし、レイテンシ記録は count/duration のみ。
