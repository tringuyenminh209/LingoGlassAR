### 2. EC2 probe 反復 - GA usage shape 確定

EC2 上で probe を回してログを採取しようとしたが、最初の試行で
`realtime.response.done` が一切出力されない問題に直面。原因切り分けを
4 段階で実施:

1. **commit `819fbc0`**: 全 OpenAI イベントの type を `realtime.event
   type=...` で INFO ログするように probe を拡張 → まだ出力なし。
2. **commit `77b35a1`**: WS handler 側にも probe 投入 (`ws.event` /
   `ws.invalid_event`) → まだ出力なし。
3. ここで原因が log handler 不在と判明。uvicorn のデフォルト LOGGING_CONFIG
   は `uvicorn.*` ロガーにしか handler を attach せず、`app.*` の
   `logger.info(...)` は root logger 経由で silent drop されていた。
4. **commit `86874de`**: `app/main.py` モジュールトップで
   `logging.basicConfig(level=INFO)` を呼ぶことで root handler を追加。
   uvicorn の `disable_existing_loggers=False` のおかげで設定が残る。

この修正後、probe は正常動作。次のテストセッションで `response.done`
の生 dict を採取するため **commit `8d7f29f`** で raw_usage dict 全体を
ログするよう probe を強化。

## 学び

1. **uvicorn の logging trap**: デフォルト LOGGING_CONFIG は uvicorn.*
   にしか handler を attach しない。`logging.getLogger("app.*")` で作った
   ロガーは root へ propagate するが root に handler がないため silent
   drop。本日 probe ログが 4 回連続で空だった原因。
   `logging.basicConfig` を main.py のモジュールトップで呼ぶのが最小
   修正。今後の backend モジュール作成時の前提として記録。

2. **probe → 契約確定の 2 段階分担は効果的**: 1 段目で OpenAI の実 shape
   を採取し、2 段目で Codex に投げる契約を lock する流れにより、Codex 側
   での仕様巡回が発生せず 1-commit 1-PR で完了。Day 7 OLED paging
   (2026-05-21) で確立した numeric-constraints-first の方針を backend
   側でも再現できた。

3. **OpenAI Realtime GA は per-minute 課金ではない**: preview-era の
   `$0.06/min` 表記から完全に per-token に移行。今後 pricing を扱う
   コードを書く時は OpenAI 公式 pricing page の単位 (per million tokens)
   と一致させる。

4. **probe 価値**: 単純な GA docs だけ見て契約を組むと、`audio_seconds`
   が独立フィールドであるという誤った前提で進んでしまっていた可能性
   が高い。実機ログ採取コストは数 commit 分だが、契約 lock 後の戻り作業
   コストを大幅に削減できた。

5. **`text_tokens=46` 固定の観察**: 5 セッションで `text_input` が常に
   46 = `SYSTEM_INSTRUCTIONS` のトークン数。つまり毎セッション同じ
   プロンプトを送っている。GA prompt caching が有効になればこの 46
   トークン×N セッション分が cached rate ($0.40/M) に落とせる。
   Day 9 latency 計測時、cached_tokens が立つかも追っておく。
