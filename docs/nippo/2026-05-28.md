# 日報 2026-05-28（S3 Day 4）

## 本日の作業

S3 Day 4 — OCR テキスト -> 翻訳 -> BLE のモバイル端到端配線（prep+impl）。

### サーフェス確定（lock）: OCR レイテンシ記録は capture アンカー

- ロック済みメトリクス `ocr_system_latency_ms = ble_ack_ms - capture_ms`（Day 1）に合わせ、音声パスの PTT press アンカーではなく **capture（撮影瞬間）をアンカー**にした。よって `bleAckMs` がそのままゲート値（音声パスのような audio_ms 差し引きは不要）。
- `latency_logger.dart` に OCR 記録ファミリを追加。ライフサイクルは e2e トレースと同型: `ocrStart(captureId)` -> `ocrMarkRecognised(charCount)` -> `ocrMarkTranslated()` -> `ocrMarkBleAck(seq)` -> `ocrFinalize()`、失敗は `ocrAbort(code)`。
- `recognisedChars` は **count のみ**（テキストは保持しない）→ BLE レグと字幕長の相関をプライバシー境界を破らずに分析可能。
- `summariseOcr()` は汎用パーセンタイル容器として `E2eLatencyStats` を再利用（stats ロジックの重複を作らない）。

### 翻訳トランスポート: 一発 REST クライアント

- 新規 `lib/services/translate_client.dart`（`session_client.dart` と同型）。`POST /v1/translate`（Day 2 契約）を叩く `TranslateClient.translate()` + `TranslateResult` + `TranslateClientError`。
- 429 -> `daily_cap_exceeded`、502 -> `translator_error`、その他非 200 -> `upstream_unavailable`。**エラーメッセージにレスポンス本文を含めない**（200 本文に translatedText が載るため、ログ漏洩を防ぐ）。

### 配線（live HTTP/camera/BLE のため Claude 実装、Codex はテストのみ）

- `lib/screens/ocr_screen.dart` を Day 3 のキャプチャ UI から拡張: capture -> `OcrScanner.recognise` -> `TranslateClient.translate` -> `BleTransport.sendSubtitle` + 各レグで latency マーク。翻訳結果を画面表示（テキストはログ/保存しない）。BLE 接続ボタン + OCR CSV コピーボタンを AppBar に追加。BLE 未接続時は端末表示のみで `ocrAbort('ble_unavailable')`（ベンチは完走キャプチャのみスコア）。
- `main.dart` に `/ocr` ルート、`translate_screen.dart` のドロワーに「Scan text (OCR)」導線を追加（Day 3 の画面は未到達だった）。
