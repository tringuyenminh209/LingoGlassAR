### 3. nginx と backend binding の切替

- nginx を TLS reverse proxy として構成し、origin の `:443` で稼働させた。
- 初回起動時、Ubuntu nginx の default site が `:80` を取得しようとして、
  既存 Docker backend の公開ポート `:80` と競合した。`/etc/nginx/sites-enabled/default`
  を無効化し、nginx を HTTPS のみで起動して解消。
- EC2 の非コミット `.env` を以下の値へ変更し、backend を再デプロイ:

```ini
API_BIND_ADDRESS=127.0.0.1
API_HOST_PORT=8000
```

- 適用後の listener:

| Port | Listener | 用途 |
|---:|---|---|
| `443` | nginx | Cloudflare からの HTTPS origin traffic |
| `8000` | `127.0.0.1` の Docker backend | nginx upstream のみ |

### 4. Cloudflare を Full (strict) へ移行

- 移行前に、origin へ直接 HTTPS 接続し、公開信頼された証明書で
  `/healthz` が `200 OK` を返すことを確認。
- Cloudflare `lingoglass.online` の SSL/TLS encryption mode を
  `Flexible` から **`Full (strict)`** に変更。
- Edge Certificates の **`Always Use HTTPS`** を有効化。

## 発生した問題と対処

| 問題 | 原因 | 対処 |
|---|---|---|
| SSH key を OpenSSH が拒否 | Windows 上の元 PEM file の ACL が広すぎた | `~/.ssh/lingoglass-osaka.pem` に制限された作業用コピーを置いて接続 |
| `bootstrap.sh` が初回に実行失敗 | Windows 経由でコピーした script が CRLF 改行だった | EC2 上の一時コピーを LF に正規化して再実行 |
| nginx が起動失敗 | default site の `:80` と移行前 backend の `:80` が競合 | default site を無効化し、nginx は `:443` のみを担当 |
| backend `.env` 更新が一度失敗 | SSH 経由の newline escape で `127.0.0.1n` が入った | 値を `127.0.0.1` に修正し、再 deploy と health check を実施 |

### 3. retry-rate 定義を trace に対して再ロック（重要）
本走は **abort/discard 0 件**だが **clean な再走が 10 件**（duplicate clean rows）。
Day 4 cooldown により double-press discard が消え、redo が「discarded エラー行」から
「clean 再走行」へ移ったため、abort のみ数えると 0% となり S1 ~50% と比較不能になる。
`lock-schema-after-trace` の教訓どおり trace を見てから定義を確定:
**retry = (clean 再走 + abort) / 全 attempts** に変更。ユーザー判断で確定。
結果 **10/60 = 17% → criterion #3 PASS**（S1 ~50% から低下）。テストを 12 に更新
（duplicate が retry に算入されることを検証）、12/12 green。
